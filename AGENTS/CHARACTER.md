# CHARACTER.md — キャラクターの資料と定義

最終更新：2026-11-11

このファイルは、キャラクター（神姫・英霊・幻獣）ごとの**調べた事実・定義の下書き・未確定事項**をまとめる。エンジンと効果 DSL の仕様は `AGENTS.md`、開発環境は `SETUP.md` に書く。

| ファイル | 書くこと |
|---|---|
| `AGENTS.md` | 仕様（ルール・エンジン・効果 DSL の部品と意味論・UI） |
| `CHARACTER.md`（本ファイル） | キャラごとの資料：何が確定していて何が不明か、出典、DSL での書き方、検証の記録 |
| `src/content/characters/<id>.json` | 実際にエンジンが読むキャラ定義（AGENTS.md §12） |
| `CHARACTER_DATA_GUIDE.md` | ゲームの説明文から定義 JSON を作る手順（言い回しと部品の対応表、確認が必要な項目） |
| `DSL_PARTS.md` | 効果 DSL の部品の一覧表 |

## 0. 運用ルール

- **1 キャラ 1 節**。下の「節のひな形」に沿って書く。
- 事実は「確定」「仮置き」「未確定」を区別する（AGENTS.md と同じ）。確定は、クライアントの確認か実機で確かめたもの。
- **JSON を作ったら、JSON を正とする。** 本ファイルの「定義」欄には JSON の下書きを置くが、`src/content/characters/<id>.json` を作った時点で、本ファイルの JSON はファイルへの参照に置き換える（二重管理を避けるため。AGENTS.md §3-3 と同じ考え方）。それ以降も、確定状況・出典・未確定事項・検証の記録は本ファイルで管理する。
- 効果が DSL の部品で書けない場合は、`custom` で逃がす前に「DSL で書けない効果」（§2）に記録し、部品の追加で対応できるかを検討する。部品を追加したら AGENTS.md §10 も同時に更新する。
- キャラ固有の未確定事項は本ファイルに書く。ルール全体に関わる未確定事項（例：アシストの連鎖）は AGENTS.md §11 に書き、本ファイルからは参照するだけにする。
- バフ・デバフの `slot` は `src/content/buffSlots.json` の ID を使う。
- バーストゲージ UP の量が説明文に書かれていないときは、`amount` を省略して +20 とし、依頼者にそのことを伝える。この節の未確定事項にも「量の記載なし（+20）」と書く。
- 効果量（`amount`）は実数値で書く。不明なら `null` とし、出典が見つかったら埋める（AGENTS.md §7.2）。
- ゲームの画像は使わない。名前とテキストデータのみ（AGENTS.md §12）。

### 定義（DSL）
**定義は `src/content/characters/eve.json` が正**（AGENTS.md §12）。以下は各部分の説明。効果量（`amount: null`）と枠 ID は仮置き。

**バースト**
→ `src/content/characters/eve.json` の `burst`・`gaugeMax`・`burstConsume`
- アビ 1 は `activateAbility` で**発動**する（AGENTS.md §10.2）。`abilityActivated` だけを記録し、`abilityUsed` は記録しないので、アシスト 1・2 の赤アビの使用回数には入らない（確定）。
- 発動したアビ 1 のダメージは、アビ 1 の効果どおり区分 `ability`。そのため「アビダメージ〇回」系のカウンターには入る。
- バーストでの発動は、アビ 1 の CT を変えない（確定）。コストも払わない。
- バーストダメージは 1 ヒット（確定）。

**アビ 1**
→ `src/content/characters/eve.json` の `abilities[0]`（eve_a1）
- n 回目の**発動**で n ヒット、10 ヒットまで。n は**戦闘全体**で数える（確定）。
- `kind: "activated"` で発動回数を数える（AGENTS.md §10.2 `useCount`）。プレイヤーの使用（即リキャ・CT 短縮で同じターンに複数回使った分も含む）とバーストでの発動の両方が 1 回ずつ入る。今回の発動も含むので、1 回目 = 1 ヒット、10 回目以降 = 10 ヒット。
- 例：T1 にアビ 1 を使用（1 ヒット）→ T1 の攻撃フェーズでバースト、アビ 1 が発動（2 ヒット）→ T2 にアビ 1 を使用（3 ヒット）。
- 雷属性はイヴの属性から決まるので、効果には書かない。

**アビ 2**

即リキャの仕様（確定）：
- **即リキャは 1 ターンに 2 回まで**。
- **そのターンの 2 回目以降の使用は、ゲージ 20 を消費する**（ゲージが 20 減る。増えるのではない）。ターンが変わると、最初の使用は無料に戻る。
- 3 回目の使用では CT は 0 に戻らない。ただし、何らかの要因（アシスト 1 の CT 短縮など）で CT が 0 まで回復すれば、**4 回目以降も同じターンに使える**（ゲージ 20 を払う。CT は 0 に戻らない）。

→ `src/content/characters/eve.json` の `abilities[1]`（eve_a2）
- **全属性ダメージ**：幻 → 火 → 水 → 風 → 雷 → 闇 → 光の順に 1 ヒットずつ（確定）。1 回の使用で区分 `ability` の `damage` イベントが 7 件記録され、そのうちダメージの属性が雷のものは 1 件。
- **ダメージ上限 UP**：持続 2 ターン、累積の上限なし、**1 段ずつ自分の持続を持って別々に切れる**（確定）。`stack.duration: "perStack"`（AGENTS.md §7.1）。効果量は不明（`null`）。
  - 例：T1 に 2 回、T2 に 1 回使うと、T1 の 2 段は T2 のターンエンド処理で切れ、T2 の 1 段は T3 のターンエンド処理で切れる。
  - すべての攻撃区分に乗るので `categories` に 3 区分を書く（初期版のエンジンは使わない）。
- コストの `when` は使う前に評価するので、`gte: 1` は「このターンにすでに 1 回以上使っている＝今回が 2 回目以降」の意味（AGENTS.md §6 コスト）。コストの `gauge: 20` はゲージを 20 減らす（効果の `gaugeUp` とは別）。
- `recast` の `when` は効果の中で評価するので、`lte: 2` は「今回がこのターンの 1・2 回目」の意味（AGENTS.md §6 即リキャ）。
- 即リキャもコストも**使用回数**（`kind` の既定 `used`）で数える。ターンが変わると自然に 0 から数え直すので、カウンター用のトークンも状態も不要。
- 同じターン内の流れ：

  | 回 | コスト | 使った後の CT |
  |---|---|---|
  | 1 回目 | なし | 0（即リキャ） |
  | 2 回目 | ゲージ 20 消費 | 0（即リキャ） |
  | 3 回目 | ゲージ 20 消費 | 5（通常どおり） |
  | 4 回目以降 | ゲージ 20 消費 | 5（CT が 0 まで回復したときだけ使える） |
- 即リキャで使った分も `abilityUsed`（赤アビ）として数えるので、アシスト 1・2 のカウンターに入る。アシスト 1 の CT 短縮で 4 回目以降が使えるようになる、という循環もこれで再現できる。

**アシスト 1**

- アビそのものには属性がないので、「雷属性のキャラが使った赤アビ」を `sourceElement`（使ったキャラの属性）で数える（AGENTS.md §4.1、§4.7）。イヴ自身も雷属性なので、イヴの赤アビも数える。
- CT -1 でアビが再使用可能になっても、自動では使わない。再使用はプレイヤーの次の操作（AGENTS.md §6.1-4）。

**アシスト 2**
→ `src/content/characters/eve.json` の `assists[1]`（eve_assist2）

- 回復の対象（雷属性の味方）と状態異常の個数（1 個）は、最初のメモの記載による。
